# retrospective（自己改善）

```
記録（worker・窓口が learning_add）→ 振り返り（ここ）→ 仮ルール（rules_set・すぐ効く）
                                                  → 正式な直し（PR・あなたの OK が要る）→ 仮ルールを外す
```

頻度と閾値は `~/.discord-loop-engine/config.json` の `retro`（既定: 完了 5 件か 7 日ごと、同じ型 3 回でルール化）。
**どちらも仮置き**。振り返りのたびに「この頻度・閾値で良かったか」も見直し、変えたほうが良ければ
ユーザーに提案する（設定の変更はユーザーが行う）。

## 手順

1. **材料を集める**: `learnings_list`（未整理の学び）、`rules_get`（今の仮ルール）、`tasks_list`（`all: true`）。
   学びが無く、完了タスクも無ければ「振り返る材料がありません」と `retro_done` して終える

2. **束ねる（advisor に任せてよい）**: 表面の文字列ではなく**根本原因が同じか**でまとめる。
   各まとまりについて、件数・根本原因・一般ルールの案（特定の Issue に依存しない命令形）を出す

3. **仮ルールにする**: `promoteAfter`（既定 3）件以上のまとまりは、仮ルールに足す。
   - 今の `rules_get` の内容に追記した全文を `rules_set` で書き込む（動いている worker にすぐ届く）
   - 各ルールには「出どころ（学びの件数と Issue 番号）」と「追加した日付」を添える
   - ルール化した学びは `learnings_promote` で印を付ける
   - 仮ルールで**安全柵を外さない**（マージに人の OK が要る・ガード hook・Codex に git 操作をさせない、など）

4. **正式な直しを提案する**: 仮ルールのうち、しばらく守られて効果があったもの（2 回目の振り返りまで残ったもの）は、
   恒久的な場所へ移す PR にする。
   - **プロジェクト固有**（そのリポジトリの規約・コマンド・確認項目）→ そのリポジトリの CLAUDE.md / AGENTS.md /
     `.claude/harness.json`。`dispatch` で worker に「この内容で Issue を立てて PR を」と頼む
   - **仕組みそのもの**（スキル・スクリプト・engine の挙動）→ `jonnity/discord-loop-engine` への Issue を起票する。
     discord-loop-engine 自体も `dle add` で登録されていれば、その worker が PR まで進める
   - どちらもマージにはユーザーの OK が要る（A-番号で届く）。マージされたら、その仮ルールを `rules_set` で外す

5. **報告する**（`reply`、1 回だけ・短く）:
   ```
   🔁 振り返り（前回から: 完了 N 件 / 学び M 件）
   - 増えた仮ルール: …（K 件の再現）
   - 提案した直し: … → Issue #… / PR #…
   - 頻度・閾値について: このままで良い / こう変えたい
   - 数字: あなた待ちで止まっていた時間の合計 … / NG … 件 / CI 失敗 … 件
   ```
   「あなた待ちで止まっていた時間」は `tasks_list` の経緯（A-番号の依頼と回答の時刻）から概算する

6. `retro_done`（summary に上の要約）で記録する
